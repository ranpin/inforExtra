取舍：flash 精度更高（F1 0.964）但为远端 LLM 调用、按 token 计费； laya 精度略低（0.916）却纯本地前向、零 token 成本、可离线——座舱场景要的是即时响应与零边际成本。 （laya vs 旧管线 omni-7b 的 17 倍加速见上方性能表、有 51 条 JSON 支撑；与 flash 的延迟倍数因 flash 延迟未入库，此处不列。）

方法：类型化决策替代巨型 prompt

旧管线把 2000-token 的抽取规则塞进 prompt 让 LLM 一次输出 JSON； 新管线改成一串封闭选项的判别式问题，由 laya 判别式作答（单次调用内并行答全部问题；管线按锚点→扫描→属性分多轮调用）。

管线

  • 候选生成：规则抽 CJK 称谓片段（姓氏过滤），不靠模型
  • 选择轮：所有候选放进同一个 softmax 竞争（forced choice），同一轮调用内定谁是真的
  • 属性轮：对每个赢家问 location（13 选项）/ identity（15 选项）
  • 代码层门控：否定句剔除、身份证据校验、称谓碎片清理

v1 → v3 的三个免微调修复

  • 否定门控：『不是/别叫我』引导的候选在代码层剔除——laya 的否定判断本身是噪声（被否定 0.71 vs 未否定 0.79，切不开）。否定句族 0.42 → 1.00
  • 锚点回退 + 增量扫描：forced choice 对「小X」类名字系统性失效（0.06 vs 同上下文 noul 0.89），置信度含糊时回退普通扫描。多人族 0.38 → 0.85
  • 称谓碎片清理：『陈部』⊂『陈部长』剔除，只认 老/部/经/医/师 首字。称谓无品牌族 0.55 → 0.95

已知短板（诚实边界）：同学边界族 0.56（『小陈同学』会被切成『陈同学』）、拉丁名 0.72、 困难负例 12 个 FP（马上/高架/张家口）——属零样本上限，微调可解。位置准确率 0.755，左右方位仍会判反。

⚠️ 分布外对抗子集（60 条，eval_adversarial.py）：上面的 0.916 是模板分布内分数。 针对代码盲区另测三族各 20 条，人名 F1 掉到 0.474—— 表外姓（翦/仝/冼/阿宝/大壮，姓氏不在过滤表）20/20 全漏召（surname 过滤的硬召回天花板）； 真实否定（别把我当成X / X不是我 / 并非X，线索不在门控表）15/20 误报； ASR 口语噪声（填充/重复）F1 0.878 基本鲁棒。 结论：瓶颈在词表覆盖与门控规则（确定性代码边界，扩表/补规则可解），不在模型对真实语音的适应力。详见仓库 README「对抗子集评测」。

本地运行（实时推理版）

仓库内的 demo/ 是真实时推理版：支持任意输入、边打字边提取（debounce 350ms）。

git clone https://github.com/ranpin/inforExtra.git
cd inforExtra
pip install -r requirements.txt        # 含 laya / torch

python demo/server.py                  # 启动时预加载模型，约 3-5s
# 浏览器打开 http://127.0.0.1:8000
  • 默认已置 v3 最优配置：JEV_BACKEND=laya JEV_CANDIDATE_FILTER=surname JEV_ASSEMBLY=forced
  • HF 主站不可达的环境会自动走本地缓存（HF_HUB_OFFLINE=1）
  • demo 服务只用 Python 标准库 http.server，不引入额外 Web 框架依赖
  • 评测复现：python compare_results.py test/results/扩充510_laya强制选择v3.xlsx test/测试集_扩充10x_gold.xlsx
