# 评测结果与基准

> jevCabin 的完整评测记录：原始 51 条、510 条扩充集、分布外对抗子集。所有数字均可用仓库内 `test/results/` 的产物离线复算。架构与后端配置见 [architecture.md](architecture.md)，概览与快速上手见 [README](../README.md)。

> **口径说明（先读）**：准确率主口径看 **510 条扩充集**（n=510，稳健；当前最优 **v5 F1 0.964，追平 qwen3.8-flash**）；**原始 51 条**是真实（非模板合成）种子集 + **性能基准载体**（延迟/吞吐在 51 条上测），样本小且题更易，其 F1（0.936/0.957/1.000）**不作与 510 条并列的头条**；**Qwen-2.5-Omni-7B 是重构前的历史基线**（「快 17 倍」的 before + 51 条 gold 来源，非当前 SOTA 对比），现代 LLM 准确率参照是 **qwen3.8-flash**（F1 0.964——v5 已追平，见 510 条表）。

> **性能对集合选择不敏感（510 条交叉验证，2026-10-22）**：`BENCH_IN=test/测试集_扩充10x.xlsx BENCH_OUT=test/results/扩充510_laya_性能.json BENCH_BACKEND=laya python scripts/bench_perf.py` 实测 p50 **0.044s**（与 51 条 0.043s 一致）、p95 0.105s / 吞吐 1243.5 条/分（低于 51 条的 0.053s / 1427——510 集多人句占比更高，候选与扫描轮次更多）。性能载体仍用 51 条的原因：真实种子句，且旧管线 Qwen2.5-Omni-7B 复测需 13984 边车 + VPN（当前环境不可得），三列同集才构成同机可比。

**结论**：
- **laya-multilingual（mmBERT-base，Apache-2.0）+ 领域候选过滤 + 强制选择组装 = 比旧管线快 17 倍、人名 F1 0.936**，零样本、纯本地、零 token 成本。Jev 范式的性能主张（毫秒级、单前向）由 laya 在本地兑现
- 剩余 4 行错误集中在：『小陈同学』边界切分（2 行，gold 要 小陈+身份同学）、否定句（2 行，『我不是陈总我叫陈部长』类）——两类均已在 v4 规则优化中免微调修复（51 条到 F1 1.000），见下文「v4 规则优化」节
- **laya 已知怪癖与本工程对策**（模型卡 Honest Limits 全部实测复现）：
  - noul 弱信号/选项顺序敏感（同一问题交换 A/B 位置分数 0.82↔0.44）→ 弃用独立 noul 扇出，改**迭代强制选择**（候选在同一 softmax 内竞争）
  - 单候选退化成二选一时随机倒向『没有人物』→ 单候选走 noul 阈值门
  - 身份高置信度幻觉（坐主驾→司机 0.97）→ **文本证据门控**：身份词必须在原文中与人名相邻出现，否则抑制（身份准确率 0.182→0.955）
  - 选项位置偏差 → 『未提及』放选项表第一位
- open-jev（英文 DeBERTa）零样本中文不可用（品牌名/方位词全高分误报）；其 512-token 上下文导致延迟随问题数严格线性（42ms/问），批量前向在 MPS 上反而慢 33%（批内 padding），默认串行
- ⚠️ 旧代码兼容性发现（旧提取函数已随 Jev 重构合并从 main 移除，以下为历史注记）：旧提取函数用 `hasattr(response, '__iter__')` 判断流式，新版 openai SDK 的 ChatCompletion（pydantic v2）可迭代 → 非流式响应被误判、解析必失败（延迟测量不受影响）。如需在 main 上修复，改用 `if EXTRACTION_STREAM:` 分支即可
- 官方 Jev API（typesafe 后端）仍待 key，拿到后可补测第四列

**v1 → v3 的三个免微调工程修复**（原始 51 条同步受益：F1 0.936 → 0.957，性能不变 p50 44ms）：
1. **否定门控**（否定句 0.42→1.00）：『不是/别叫我/不叫』引导的候选在代码层剔除，不进模型——laya 零样本的否定判断是纯噪声（被否定 0.71 vs 未否定 0.79，任何阈值切不开），而否定句式是确定性表层句法
2. **锚点回退 + 增量扫描**（多人 0.38→0.85）：实测 laya 的强制选择对『小X』类名字系统性失效（三人句第 2 轮 小李 0.06，同上下文 noul 0.89）。改为：第 1 轮强制选择定锚点；『没有人物』胜出但置信度 <0.7（含糊）时回退普通 noul 扫描（多人句漏判实测 0.62 vs 真负例 0.77-0.86，据此门控）；锚点确认后对剩余候选做带上下文的 noul 扫描
3. **称谓碎片清理**：『姓+多字称谓首字』的 2 字片段（陈部 ⊂ 陈部长）剔除——碎片会稀释强制选择的 softmax（实测 [陈部, 陈部长] 时倒向『没有人物』）。只认真正称谓碎片（老/部/经/医/师 开头）：宽泛剔除会把 江湖/宋城 类困难负例削成单候选、落进 noul 路径产生误报（江湖救 noul=0.73，强制选择能正确以 0.86 拒绝）

结论：
- **laya v5 已追平 flash**（F1 同为 0.964），且 laya **单条 ~43ms、零成本、纯本地**（flash 为远端 LLM 调用，车机/离线场景不可用；laya 目前仅在 Mac 实测，车机/嵌入式部署为未来工作）
- laya 剩余弱点（v5 后）：困难负例 12 FP（姓氏开头的普通词：马上/高架/张家口——零样本判别上限，微调可解）；位置准确率 0.879 的余量是多人绑定与区域词 gold 口径行（左右混淆已由 v5 规则 6 修复，见「v5 规则优化」节）；同学边界 0.56→0.96、拉丁名 0.72→1.00 已由 v4/v5 规则修复
- 拉丁名族 laya 反超 flash（0.96 vs 0.24）：代码级片段提取 + 裸称谓清理天然剥离称谓，LLM 把『bob小姐』整体当名字
- Qwen3.8 系（max/flash）默认开思考；`enable_thinking:false` 平台可透传（`eval_llm_baseline.py --no-thinking`），关思考后 flash 单条 p50 1.29s，开思考的 max 单条 ≥7s（511 条跑不完，已弃）

## 对抗子集评测（分布外，2026-10-19）

510 条扩充集是**模板构造**的（人名全从 `SURNAMES` 表抽、否定句式与 `_is_negated` 的 `NEGATION_CUES` 同源），属**分布内**评测。为暴露召回天花板与否定泛化缺口，另建 60 条对抗子集（`eval_adversarial.py`，三族各 20 条，全部针对代码盲区设计）：

| 族 | 设计意图 | 人名级结果 | F1 |
|---|---|---|---|
| 表外姓 | 姓氏不在 `SURNAME_CHARS`（翦/仝/冼/佟…）、外号非「小X」（阿宝/大壮） | **20/20 全漏召**（FN=20） | **0.000** |
| 真实否定 | 否定线索不在 `NEGATION_CUES` 或置于名字后（别把我当成X / X不是我 / 并非X / 没来） | **15/20 误报**（FP=15） | **0.000** |
| ASR噪声（对照） | 口语填充/重复/语气尾词，人名仍在表内 | 18 TP / 3 FP / 2 FN | 0.878 |
| **合计** | — | — | **0.474** |

**结论（诚实边界）**：分布内 0.916 **不是真实座舱语音的分数**，而是模板分布内的分数。两个盲区是**确定性代码边界**、非模型能力问题：

- **表外姓 = 硬召回天花板**：`surname` 过滤只为「姓开头 / 小X / 复姓 / 拉丁词」生成候选，表外姓根本进不了候选集 → 必然漏召。扩姓氏表或改 `span` 模式可解，但会重新引入品牌/方位词误报（这正是当初选 surname 过滤的代价）。
- **真实否定 = 门控泛化缺口**：`_is_negated` 只匹配名字前 3 字内的 6 个固定线索；「别把我当成 / X不是我 / 并非 / 没来」全绕过。但 20 条里仍有 5 条被 laya 模型自身正确拒绝（「缺席 / 不来了」类），说明模型有部分否定判断力，是代码门控没覆盖全。
- **ASR 噪声鲁棒（0.878）**：口语填充/重复不破坏表内人名提取 → 瓶颈在**词表覆盖**，不在模型对真实语音的适应力。

复现：`.venv/bin/python scripts/eval_adversarial.py`（产物 `test/对抗集.xlsx` + `test/对抗集_gold.xlsx` + `test/results/对抗集_laya_v4.xlsx`；v3 预测仍留库中）。

> **v4 规则修复后**：合计 F1 0.474 → **0.907**（表外姓 0.000→0.824、真实否定 FP 15→1、ASR 噪声 0.878→1.000），规则与剩余留白见下文「v4 规则优化」节。

## v4 规则优化（2026-10-21）

针对对抗子集暴露的三类代码盲区 + 510 集内同学边界/拉丁名弱点，落地四条确定性规则（全部代码层，零新增模型调用，性能不变 p50 0.043s）。每条规则独立通过三集回归门（对抗集 + 51 条 + 510 条；规则 1/2 在 51/510 上行级零差异）：

| 指标 | v3 | **v4** | 变化 |
|---|---|---|---|
| 510 条人名 F1 | 0.916 | **0.944** | +0.028 |
| 510 条行级全对 | 444/510 (87.1%) | **462/510 (90.6%)** | +18 行 |
| 510 条位置 / 身份准确率 | 0.755 / 0.796 | **0.799 / 0.885** | +0.044 / +0.089 |
| 51 条人名 F1 | 0.957 | **1.000**（行级 50/50） | +0.043 |
| 对抗集合计 F1 | 0.474 | **0.907** | +0.433 |

**规则 1 候选生成扩展**（对抗集：表外姓 0.000→0.824、ASR 噪声 0.878→1.000）：
- 姓氏表补 8 个无普通词冲突面的生僻姓（翦仝佟佘菅庹慕言）；商/迟/展/初/福/贵 等易撞词姓仍排除（同 司/老/同 原则）
- 阿X 昵称模式（与小X 并列）；「单字+称谓」锚点（X老师/X医生/X经理/X老板/X师傅——这些词几乎不出现在非人物词的词尾；总/工 因撞 总结/工作 不收）
- 句尾语气词入停用字（哈嘛哦诶嗯呗啦咯呀哟哇嘞没）；叠字碎片清理（王总王 ⊂ 王总王总）
- 余 6 FN 为设计内排除：商总/展总/初工（易撞词姓）+ 大壮/胖子（大X/X子 模式冲突面大）+ 佟老板（单候选 noul 门 0.5 阈值问题）

**规则 2 否定门控泛化**（对抗集：真实否定 FP 15→1）：
- 前向线索扩词：并非/当成/算不上/哪里是/别记成（窗口保持 3 字——扩到 4 会误杀「不是啊，小李在主驾」类话语否定+真实人名句式）
- 后向缺席/纠正线索（新机制）：不是我/是别人/没来/不来/缺席/不在车上/没上车，只关联最近的前置候选（≤8 字、可跨逗号）并连带其重叠候选——防「周老师来了，小李没来」误杀前者、防「赵总并」类碎片劫持关联
- 已知留白 1 FP：「我没说我是X」（线索与人名隔 2 字，窗口内无法覆盖）

**规则 3 称谓后缀拆分与身份抑制**（510：同学边界 0.56→0.96、拉丁名 0.72→0.96、身份准确率 0.796→0.885）：
- 拆分：赢家形如「X+称谓」（陈同学）且原文恰有止于称谓起点的重叠候选（小陈）时，拆成 name=小陈 + 身份=同学；文中无「小陈」的「陈同学」整体留名（gold 约定的两个分支）
- 身份后缀抑制：身份是名字自身后缀时置空（陈同学+同学 / 陈部长+部长 → 称谓留在名中，与 gold 约定一致）
- 裸称谓（bob小姐 的 小姐）不作独立人物；候选清理改两遍（防 冯老师 类完整称谓被误杀——其前缀 冯老 本身才是待清理碎片）

**规则 4 位置文本证据门**（510：位置准确率 0.755→0.799，+20 行位置幻觉修复）：
- 原文没有任何位置词时，位置回答必是幻觉（困难负例 马上/高架 全部幻觉出位置；否定句/自我介绍 gold 位置为空也被幻觉）→ 置空
- 宽松版 = 原文存在任一位置词即保留（不验证预测的具体选项词）：gold 与问题措辞都允许 右后→右后座 类同义映射，严格验证会误杀 51 集 2 行正确行
- **两级阈值（裸人物→更高 is_person 阈值）实证否决**：裸 TP 分数 0.52-0.81（否定句/自我介绍赢家）与裸 FP 0.59-0.98（困难负例）完全重叠，模拟任何阈值净损（F1 0.942→0.937@0.6，随阈值升高单调恶化）

**温度校准调查**（`fit_calibration.py`，结论 = 不接入管线）：
- 510 条域内集按管线同形态问题构造 gold 标签，收集 6797 条 logits 记录拟合：域内 ECE 0.50（严重过自信），拟合撞钳位——choice 型想要 T=7.5、choice:2 桶想要 T=6833，全部被钳到 laya 上限 5.0；校准后 holdout ECE 0.37 仍高

| 510 条行级全对 | 462/510 (90.6%) | **481/510 (94.3%)** | +19 行 |

行级归因（v4 vs v5 逐行 diff）：**19 行恢复（全部为『[品牌]的[人名]』句式）、0 行回退**。

**规则 5 介绍线索锚点**（修『我是小张，坐在副驾』漏检）：laya 对自我介绍句中的小X类名字 noul 系统性低分（实测 0.4407 < 0.5 阈值，而同句位置问题 0.9995 全对——人物门是唯一失效环节）。『我是/我叫/叫我/喊我/称呼我/我的名字是/这是/那是/他叫/她叫/他是/她是』紧邻候选时直接作确定性锚点、跳过模型门控（否定门控先行，『我不是X/别叫我X』已剔除，不冲突）；命中句选择轮问题数 1→0。

**规则 6 位置文本证据绑定**（修『后排左边是我女儿小雨』答成 后排右边）：laya 位置 choice 左右系统性混淆（实测 后排右边 0.307 > 后排左边 0.189，证据词就在原文逐字出现）。原文中与人名确定性绑定的座位词（前向 [loc]…是/坐/在…[name] / 后向 [name]…在/坐…[loc]，≤8 字、不跨句读、不跨其他赢家）与模型回答冲突时以原文覆盖：座位级绑定词 vs 座位级异座回答 → 覆盖；座位级绑定词 vs 区域级粗答（后排 vs 后排左边）→ 覆盖；同座异名（右后→右后座）保留模型答案（gold 允许同义映射）；模型判『未提及』不补填（否定句/自我介绍 gold 位置为空的约定）。510 位置准确率 0.799→0.879 的主要来源。

**规则 7 公司信息提取**（新需求：提取信息包含常见互联网/汽车公司）：输出新增 `company` 字段。~90 词公司词典（汽车整车/新势力/供应链 + 互联网/科技）+ 就近绑定（前向『[品牌]的[人名]』/ 后向『[人名]是[品牌]』，≤4 字、gap>0 须含连接词 的/是/在/来自/属于、不跨句读与其他赢家、品牌出现不与人名重叠）。三条配套候选清理：
- **包含清理**：原文出现更长公司词时（阿里 ⊂ 阿里巴巴），短词的阿X昵称义让位公司义
- **两用词公司义清理**：『小鹏的周平』的 小鹏（公司词兼人名候选）按公司义剔除人物候选——否则它既是人物 FP（gold 只有 周平）又挡住公司绑定
- **品牌线索锚点**：『[公司词]的[候选]』直接作确定性锚点——两用词清理后剩余唯一候选若走单候选 noul 门会因『X的Y』句式低分漏检（实测 周平 <0.5）
- **同起点线索去歧义**（规则 5/7 共用）：田子 ⊂ 田子涵 同起点双命中取最长者（跨起点才是真歧义、交回模型）——3 字名（张桂英/田子涵 类）全部受益，品牌位置族行级 0.84→**0.99**、FP 归零
